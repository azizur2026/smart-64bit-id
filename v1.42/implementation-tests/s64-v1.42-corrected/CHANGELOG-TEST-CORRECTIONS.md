## Revision 2 — isolated CT-07 Engine allocation

- Corrected CT-07 so it no longer assumes Engine ID 1001 in the disposable database.
- Each run provisions a new Engine ID (`MAX(engine_id)+1`) under a MariaDB advisory lock.
- Existing test Engine rows, allocations, and counters in `s64_ct07_disposable` are never deleted or reset.
- The selected Engine ID is recorded in `evidence/CT-07/engine-id.txt`.
- CT-07 encodes the selected Engine ID into S64 values and uses it for all counter/allocation queries.
- CT-08 now reads that recorded Engine ID and compares the same Engine's snapshot before and after restart.
- The original `s64_test` Engine 1001 and its recorded next counter of 100001 are not accessed by CT-07/CT-08.
- Each new isolated test Engine starts at Local ID 1; this does not reset or alter the original Engine 1001 counter.
