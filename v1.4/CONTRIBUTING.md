# Contributing to SMART 64-Bit ID

Thank you for your interest in contributing to SMART 64-Bit ID.

SMART 64-Bit ID is developed as an open project, and useful
technical contributions are welcome.

## Before Contributing

Please read:

- `README.md`
- `docs/SPECIFICATION.md`
- `docs/ARCHITECTURE.md`
- `docs/RULES.md`
- `CLA.md`

The technical architecture and core specification are maintained
carefully. Contributions should preserve the defined identity,
allocation, routing, lifecycle, persistence, and failure
semantics unless a specification change is intentionally proposed.

## Types of Contributions

Contributions may include:

- documentation improvements;
- corrections and clarifications;
- diagrams and examples;
- benchmark methodology;
- research and analysis;
- reference implementations;
- tests and validation tools;
- bug fixes;
- compatibility improvements; and
- carefully reviewed specification proposals.

## Pull Requests

Before opening a pull request:

1. Keep the change focused.
2. Explain what was changed and why.
3. Identify any technical or behavioral impact.
4. Update relevant documentation when necessary.
5. Do not include secrets, credentials, private data, or
   unrelated material.
6. Ensure that examples and benchmark claims are clearly
   identified as examples or measured results.
7. Do not present unsupported performance claims as guarantees.

## Technical Specification Changes

Changes to the core SMART ID specification require additional
review.

Examples include changes to:

- the 64-bit layout;
- identity semantics;
- Engine allocation rules;
- Local ID allocation rules;
- uniqueness requirements;
- routing semantics;
- lifecycle semantics;
- failure behavior; or
- versioning semantics.

Such changes should be clearly identified as specification
changes rather than ordinary documentation corrections.
